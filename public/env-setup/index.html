Env Setup

The complete, updated cloudflare-env-import.env file — every variable, every key, ready to import into Cloudflare Pages. Follow the steps below exactly; the whole site, the API, the Telegram bot and the GET endpoints are configured from this single file.

🔒 Security warning

This page ships with placeholders only — real API keys are never published here. An earlier version did embed live keys, and GitHub push protection blocked the push: anyone could read them in the page source. Use the generator below — the keys you type stay in your browser only, are sent nowhere, and produce the real import file. Never commit real keys to the repo.

1. Import into Cloudflare Pages (exact clicks)

  1. Open dash.cloudflare.com → Workers & Pages → aigateway.
  2. Go to Settings → Variables and Secrets.
  3. Click + Import .env → select the downloaded cloudflare-env-import.env file (or copy-paste the whole block below into the first variable's edit box using Import .env — it parses KEY=value lines). Confirm.
  4. Switch to the Preview environment tab on the same page and repeat the import there too.
  5. Redeploy: Deployments → latest deployment → ⋯ → Retry deployment (or push any commit). Variables only take effect after a deploy.

4. After importing — verify in 60 seconds

  1. Open /api/v1/config → should show version: 1.4.0 and your base URL.
  2. Click /ask?prompt=Say GATEWAY-OK → JSON answer straight in the browser.
  3. Open /status/ → provider tiles should be live.
  4. If you set the Telegram vars, run the setWebhook command from the Telegram page and message your bot.
Common issues
  • UPSTREAM_AUTH_ERROR → the provider key is wrong/expired: update it here and redeploy.
  • Variables changed but nothing happened → you forgot the redeploy (step 1e).
  • Import button missing → use the classic "Add variables" flow and paste each KEY=value, or update Cloudflare dashboard language/permissions — the Import .env button exists on all current Pages projects.
  • "Variables are managed through wrangler.toml" → a wrangler.toml was added back to the repo. Delete it, commit, redeploy — dashboard variables become editable again. This project ships WITHOUT that file on purpose.
